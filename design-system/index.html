How it works

Three tiers of tokens. Primitives are raw values (the umber, plaster, stone and gold ramps; the type scale; the space scale). Semantic tokens say what a value is for: --surface, --text, --text-muted, --accent, --line. Components only ever use semantic tokens.

Rooms. A section declares its ground with data-room="dark | deep | plaster | stone | photo". The room remaps the semantic tokens for everything inside it, so a button, a card or a quote works on every ground with no variant classes.

Cascade layers. main.css imports tokens → base → layout → components → pages → utilities in that order. A later layer always wins, so page rules never need !important.

Where things live

  • assets/css/tokens.css: every color, size, space, radius, duration.
  • assets/css/components.css: reusable pieces (index at the top of the file).
  • assets/css/pages.css: compositions used on one page only.
  • assets/js/site.js: the sitemap, header, footer, drawer, mark and shared behaviors. Add or rename a page there once.
  • assets/data/gatherings.js and library.js: content that a CMS will own later.
  • assets/img/icons.svg: the icon sprite.
